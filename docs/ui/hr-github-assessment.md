# NEUTRAL GITHUB ASSESSMENT SPECIFICATION (PHASE 6 BASELINE)

Tài liệu này đặc tả Phân hệ Đánh giá GitHub Cá nhân Trung tính (Neutral GitHub Assessment).

---

## 1. NGUYÊN TẮC ĐÁNH GIÁ TRUNG TÍNH (NEUTRAL OBSERVATION PRINCIPLE)

* **Ngôn ngữ Quan sát Trung tính:** Sử dụng cụm từ khách quan như *"Hoạt động quan sát gần nhất X ngày trước"* hoặc *"Tín hiệu hoạt động quan sát (Activity Signal)"*.
* **Tránh Ngôn ngữ Suy đoán Cảm tính:** Tuyệt đối **không** dùng các từ ngữ định kiến như *"ứng viên làm việc chăm chỉ"* hay *"dự án phổ biến = lập trình viên giỏi"*. Số lượng Stars và Forks chỉ được coi là tín hiệu tham khảo bổ trợ.

---

## 2. HIỂN THỊ CHI TIẾT TÍN HIỆU GITHUB

1. **Tổng số Repositories Công khai:** Thống kê số lượng mã nguồn mở.
2. **Phân bố Ngôn ngữ (Language Distribution %):** Biểu đồ tỷ lệ phần trăm các ngôn ngữ lập trình xuất hiện trong mã nguồn.
3. **Tín hiệu Hoạt động (Activity Signal):** Ghi nhận ở các mức `HIGH`, `MODERATE`, `LOW`, `LIMITED_OBSERVABLE_ACTIVITY`.
4. **Mã nguồn Phù hợp (Relevant Repositories):** Danh sách thẻ repo nổi bật khớp với công nghệ của bài đăng JD (Tiêu đề, Mô tả, Ngôn ngữ chính, Stars, Forks, Số ngày cập nhật).

---

## 3. XỬ LÝ TRƯỜNG HỢP KHÔNG CÓ GITHUB HOẶC NGÀNH PHI KỸ THUẬT (FALLBACK STRATEGY)

* Nếu ứng viên chưa liên kết GitHub hoặc bài đăng thuộc ngành phi kỹ thuật (Marketing, Finance, HR...):
  * Giao diện hiển thị trạng thái trung tính: **"GitHub: Not connected"** hoặc **"GitHub: Not used for this role"**.
  * **Tuyệt đối không hiển thị điểm GitHub Score = 0**.
  * Chuyển sang chiến lược Fallback: **Overall Score = Core JD-CV Score**, đảm bảo ứng viên không bị trừ điểm phạt vô lý.
